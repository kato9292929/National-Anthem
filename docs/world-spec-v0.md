# ナショナルアンセム — 世界設定スペック v0

v0 作業指示書・差別化指示書と併用する。差別化指示書 §3 の「世界設定と固有名」（§0–§3）と
「経済の重心」（§4）を、本書で確定する。

**世界設定**: 古代メソポタミア南部の交易都市。シュメール人とアッカド人（セム語族）が隣り合って暮らし、
二言語の商人名・地理を記録する必要から楔形文字が発達した世界。石・金属・良質な木材を欠く南部が、
遠隔地（インダス／エジプト／アナトリア／イラン方面）と交易する。

## 0. 前提の確認（非流用）

これは想像の古代交易都市を建てる**別 fiction**。ancient world プロジェクト（検証コンテンツ）の
資産・データ（aw-data）・禁則（生成画像や復元図を使わない等）は流用しない。
共有するのは**美学のインスピレーションだけ**。ここでは想像の空間を自由にレンダしてよい。

この制約は機械可読側にも `constraints.no_reuse` として持たせる（`world/world.config.json`）。

## 1. 芯との対応（差別化の背骨）

この世界の史実要素が、National Anthem の芯にそのまま対応する。ここが world と機能の接続点。

| 史実要素 | 芯（機能） | 対応の中身 |
| --- | --- | --- |
| 円筒印章 | identity / standing | 本人の署名。誰の印か＝参加者の identity。押印の履歴＝実績・来歴。standing が room の開閉に効く仕組みを印章で表現できる |
| 粘土の封筒（case tablet） | 検証機密の決済 | 契約タブレットを外側の粘土ケースで封じ、条項を見せない史実の形。Arcium MXE の「`payment_valid` だけ返し、送金元・金額・エンドポイントは封じる」に対応。追跡不能化ではなく、**封じて検証する**線と一致 |
| 商人（tamkārum）と交易代理人（šamallum） | 人間とエージェント | principal の商人が遠隔地を回る代理人に委託し、封印タブレットで account を精算した史実の構造。人間＝principal、自律エージェント＝代理人がそのまま乗る |
| 封印タブレットによる account 精算 | escrow ＋ arbitration | 依頼・受注・納品・精算・係争の解決を、タブレットの記録として表現できる |

この対応は**史実の基盤として提示する**。どこまで world の演出に使うかは加藤さん判断。
機械可読側では各行を `core_mapping[]` に `presentation_depth: "TBD"` 付きで持たせ、演出の強度だけを後から差し替える。

## 2. 取引カテゴリ（stall 分類）

禁制品ネーミング（差別化指示書で既に不採用）の代わりに、**実際の交易品で中立に分類する**。史実準拠。

この分類は副モジュール（物販ストアフロント）の分類であり、主モジュールの commission board に従属する（§4）。

### 南部が輸入する側（不足資源）

- **木材** — レバノン杉／アマヌス山地方面
- **金属** — 銅＝マガン／アナトリア方面、錫＝東方ルート
- **石・宝石** — ラピスラズリ＝バダフシャン方面、紅玉髄＝インダス方面

### 南部が輸出する側（生産物）

- **繊維・織物**
- **穀物・ナツメヤシ等の食料**
- **完成品・工芸**

### 遠隔地の交易相手

史実の地名が使える（発見済みの固有名詞なので流用でなく史実引用）:
ディルムン（湾岸の中継地）、マガン、メルッハ（インダス）、アナトリア、エジプト。

市場の経済ロジックは「**繊維・穀物を輸出し、木材・金属・石を輸入する**」で立つ。

## 3. 参加者モデル

v0 の参加者モデル（人間／エージェントが同じ板）を**変えない**。世界設定を重ねるだけ。

- **人間＝商人（principal）** としても、板の売り手としても立てる。
- **エージェント＝交易代理人**（§1）として、無人で quoting／受発注／精算する。
- 二言語で記録する必要から文字が発達した、という史実は、取引をエージェント可読の記録層に落とす
  動機付けとして world 側に置ける（機能は v0 のまま）。

## 4. 経済の重心（v0 確定）

**決定: 経済の重心 = 交易代理＋記録（commission / consignment ＋ 封印精算）。物販ストアフロントは副次モジュール。**

差別化指示書 §3「経済の重心」をここで確定する。機械可読側は `economy`（`world/world.config.json`）。

### 4.1 板の構成（モジュール順）

- **主: 委託・受発注ボード（commission board）** — principal が委託を出し、代理エージェントが遠隔交易の
  各レグを実行し、封印精算で account を締める。
- **副: 物販ストアフロント（stall 買い物）** — §2 の中立分類（木材・金属・石／繊維・穀物・完成品）の
  まま、主モジュールに従属させる。

### 4.2 芯との対応（§1 を継承・確定）

| 役 | 割り当て |
| --- | --- |
| principal | 人間／エージェント（tamkārum） |
| 実行 | 代理エージェント（šamallum） |
| 精算 | 封印タブレット（case tablet）＝検証機密の決済（Arcium MXE、`payment_valid` のみ） |
| standing | 円筒印章の履歴（完了・精算済み委託の蓄積）が room の開閉に効く |
| escrow ＋ arbitration | 委託の記録と係争解決 |

§1 の対応表と同じ束縛を、経済の重心の側から確定したもの。両者が食い違ったら §1 の対応が先で、
本節はそれに役を割り当てているだけ、と読む。

### 4.3 v0 との対応

- v0 の **M7（バウンティ板・escrow・arbitration）を主モジュールに昇格**し、commission board として実装する。
- v0 の**物販は副モジュールとして分離実装**する。差別化指示書の「物販と受発注を別モジュールで分離実装」を、
  順位を確定した形。

### 4.4 未確定（実装時に v0 の範囲で詰める）

commission の具体フロー — **レグ数・遠隔地の扱い・精算単位** — は実装時に v0 の範囲で詰める。
推測で仕様を埋めない。config では `economy.commission_flow.*` を `TBD` / `confirmed: false` で置く。

## 5. プレースホルダ（加藤さん確定まで）

推測で固有名を埋めない。確定まで仮値で通し、埋めた箇所は未確定ラベルを残す。
機械可読側では `naming.*.confirmed: false` が未確定を表す。

| キー | 仮値 | 状態 |
| --- | --- | --- |
| 市場そのものの名称 | `MARKET_NAME` | 未確定（加藤さん） |
| 地区名 | `DISTRICT_NAME` | 未確定（加藤さん） |
| NPC 名 | `NPC_NAME` | 未確定（加藤さん） |
| stall の固有名 | `STALL_NAME` | 未確定（加藤さん） |

§2 の史実地名（ディルムン等）は引用してよい。world 固有の命名（架空の店・人物）は加藤さん判断。

## 6. 範囲外

- **ビジュアルの確定**（配色・アセット・レイアウト・UI の見た目）は加藤さん側。
  Donwood のトリートメントに古代モチーフを重ねるか置き換えるかを含む。
  CC はパラメータ化・差し替え可能な形で組む → `presentation` ブロックは値を持たず `TBD` のまま置く。
- ancient world プロジェクトの資産・データ・禁則は非流用（§0）。

## 7. この仕様の使い方（実装側）

- 正典は本書。`world/world.config.json` は本書を機械可読にしたもので、**本書と矛盾したら本書が勝つ**。
- 固有名は必ず config 経由で引く。ソースにリテラルで市場名・地区名・NPC 名を書かない。
- `confirmed: false` の値は UI に出す前に確定を取る。仮値のまま出す場合は仮値であることが分かる形にする。
- 見た目に関わる値は `presentation`（現在すべて `TBD`）にだけ置き、ロジック側に散らさない。
- モジュールの順位は `economy.modules` が持つ。物販側の都合で commission board の仕様を曲げない（§4）。
